U8 外挂 MRP
计划平台建设方案

以 U8 为业务与财务底座，建设可解释、可模拟、可审核、可追溯的独立物料需求计划能力。

对象：UFDATA_001_2020版本：讨论稿 V1.0日期：2026-07-30
Executive Summary

执行摘要

01

独立库不在 U8 生产库承载运算

建议定位

外挂系统承担需求汇总、BOM 展开、净需求、时间排程、模拟与计划协同；U8 继续负责基础档案、正式业务单据、库存和财务核算。

推荐模式：外挂计算 → 计划员审核 → 通过官方接口或受控导入写回 U8。

实施原则

  • 第一阶段不直接修改 U8 业务表。
  • 以一致性数据快照作为每次运算输入。
  • 与 U8 原生 MRP 并行对比，形成差异解释。
  • 业务规则参数化，不把口径写死在程序中。
  • 输入、过程、结果、人工调整和写回全部留痕。
重要边界：外挂可以替代“计划计算与协同”，但不能绕开 U8 的单据校验、审批、库存台账和财务核算逻辑。

  • 支持多方案模拟，不污染正式业务数据。

  • 缩短计划员整理 Excel 和跨部门确认时间。
  • 保留每次计划版本，支持事后复盘。

部署隔离

外挂数据库、应用服务与任务服务独立部署，计算不占用 U8 生产库的 CPU、内存和临时空间。

读取策略

使用专用只读账号，按水位增量同步；正式运算前生成带时间戳的一致性快照。

写回策略

计划员确认后，通过 U8 官方接口或受控导入生成草稿/申请；禁止直接拼接业务表。

必须先定义“可用库存”

是否包含待检、冻结、代管、项目库存、不合格品、调拨在途和已分配量，将直接决定结果。该口径必须由计划、仓库、采购、生产共同签字确认。

必须先定义供需去重

采购在途、生产在制、委外、调拨、请购和预测之间可能存在上下游关系。计算前需要建立来源链，避免同一笔供应或需求被重复计入。

MRP Engine

计算模型与核心能力

05

01 需求归集

销售订单、预测、备货、维修及人工需求统一进入需求池，按来源、日期、优先级和维度去重。

02 低层码与展开

校验 BOM 环路，计算低层码；按有效版本逐层展开，处理损耗、固定用量、虚拟件和替代策略。

03 供需平衡

按日期顺序消耗可用库存和已确认供应，保留每一次匹配关系，计算缺口及可承诺量。

04 批量处理

支持按需、固定批量、最小/最大批量、批量倍数、周期合并与供应商最小起订量。

05 时间排程

结合采购、生产和检验提前期及工作日历，倒排建议下单、开工、到货和完工日期。

06 例外与追溯

输出提前、推迟、取消、加急、超期和参数缺失；由建议反查需求，也可由需求追查供应。

净需求基础公式

净需求 = 毛需求 − 可用库存 − 有效在途供应 + 安全库存

实际算法按时段逐笔计算，并叠加批量、日历、优先级、替代关系及供需锁定，不采用单次汇总相减。

结果对象

采购建议
物料、数量、日期、供应商候选
生产建议
产品、数量、开完工日期、来源需求
缺料清单
缺口日期、影响订单、责任部门
例外消息
提前、推迟、取消、加急、失效

Developer Flow · Snapshot

数据同步与一致性快照

10

输入

  • 上次成功水位
  • 计划截止时间 T0
  • 组织与业务范围
  • U8 源表/视图清单

处理

读取增量 → 写入镜像层 → 主外键映射 → 业务状态标准化 → 形成不可变快照 → 行数/金额/数量对账

输出

  • Snapshot ID
  • 源水位与抽取时间
  • 每表行数与校验和
  • 数据质量问题清单

建议实现顺序

1. 读取水位modify_time / identity / rowversion
2. 暂存stage_* 表
3. 标准化编码、单位、状态
4. 对账数量与关键汇总
5. 门禁错误阈值判断
6. 冻结快照只读

一致性策略

  • 优先在 U8 侧启用允许的快照读取机制；不可用时按业务对象顺序抽取并记录统一 T0。
  • 订单主子表必须使用同一批水位，避免主表已更新而子表未更新。
  • 计算只读快照表，不在长事务中扫描 U8 生产库。
  • 源记录变更不覆盖历史快照，保证结果可重放。

质量门禁示例

  • BOM 环路、缺失父/子件：阻断。
  • 单位换算为零、需求日期为空：阻断。
  • 提前期缺失：按配置决定阻断或使用默认值。
  • 负库存、超期供应：警告并进入例外工作台。
  • 主子表数量突降超过阈值：阻断并告警。
开发注意：部分 U8 表不具备统一修改时间字段，不能假定所有对象都能按时间戳增量同步；需按对象选择 rowversion、最大 ID、业务日期＋回看窗口或周期性全量比对。

按低层码迭代

for level in 0..max_low_level: items = load_items(level) for item in items: demand = load_gross_demand(item) supply = load_effective_supply(item) result = time_phased_netting(demand, supply) planned_orders = apply_lot_and_calendar(result.shortage) save_pegging(result.matches) explode_to_children(planned_orders, effective_bom) commit_checkpoint(run_id, level)

单物料时段平衡

available = opening_available for bucket in ordered_buckets: available += confirmed_supply[bucket] for demand in sort(priority, need_date, order_no): used = min(available, demand.open_qty) create_pegging(supply_source, demand, used) available -= used shortage = demand.open_qty - used if shortage > 0: qty = lot_sizing(shortage, item_policy) due = demand.need_date release = backward_schedule(due, lead_time, calendar) create_planned_order(qty, release, due)

排序键

需求优先级 → 需求日期 → 客户/订单优先级 → 单据号。

维度键

物料＋仓库＋自由项＋项目＋批次属性，按企业口径配置。

冻结区

冻结期内保留已确认计划，只产生例外消息，不自动重排。

并行边界

同一低层码、无依赖物料可分片并行；层级之间必须有屏障。

关系和保留策略

关系基数用途实现约束
Snapshot → Run1 : N同一输入运行多个参数方案快照冻结后不可更新
Run → Demand / Supply1 : N保存标准化输入，便于重放按 run_id 分区/索引
Demand ↔ Supply/PlanN : N通过 Pegging 保存逐笔匹配matched_qty 大于零，维度必须一致

  • 追踪：从页面请求追踪到计算任务、数据库语句及 U8 接口调用。
  • 告警：水位停滞、行数突变、运行超时、死信、重复写回和结果突变。
事务边界：一次完整 MRP 不使用单个数据库大事务。每个阶段写入带 Run ID 的隔离结果，完成后原子更新阶段状态；失败时清理或覆盖该阶段的暂存结果。

风险、验收与决策建议

17
风险等级应对措施
库存、在途、在制口径不一致高建立口径矩阵，以典型订单逐笔验证并由业务会签
BOM 版本、替代和二开规则复杂高先限定试点产品族，建立规则测试用例和版本管理
外挂与 U8 原生结果存在差异中输出逐笔差异原因，不以“总量接近”代替逻辑一致
生产库查询影响业务中增量同步、错峰全量、独立快照和查询超时保护
自动写回造成重复或错误单据高人工审批、幂等键、草稿模式、限量灰度和一键停用

建议验收指标

  • 试点范围 BOM 展开正确率：100%
  • 供需来源可追溯覆盖率：100%
  • 关键物料净需求准确率：≥ 98%
  • 重复建议或重复写回：0
  • 全量运算时间：满足业务批次窗口
  • 关键失败可恢复、可重跑、可审计

上线门槛

  • 至少连续 3 个计划周期并行运行。
  • 高价值/关键物料差异全部闭环。
  • 采购、生产、仓库和计划共同签字。
  • 完成备份恢复、接口回滚和故障演练。
  • 未达门槛前只输出建议，不自动写回。

决策建议

批准开展“小范围、只读、可对比”的概念验证（PoC）。选择一个 BOM 复杂度中等、业务代表性强的产品族，以一个完整计划周期的数据验证算法和口径。PoC 通过后再建设全量工作台，最后启用受控写回。

本报告为面向开发团队的方案讨论稿；正式实施前需完成 U8 版本、接口许可、业务口径和二开对象专项确认。
