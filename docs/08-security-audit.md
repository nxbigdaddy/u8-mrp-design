# 08　安全与审计

## 1. 威胁重点

系统连接核心ERP并包含采购、成本、客户和生产数据，主要风险为凭据泄露、越权查询、错误写回、结果篡改、批量导出和审计缺失。

## 2. 身份与权限

- 通过企业 OIDC/AD 单点登录，禁止自建弱密码体系。
- RBAC角色：查看、计划、审核、发布、接口运维、系统管理。
- ABAC数据范围：组织、仓库、物料分类、计划组。
- 审核人与提交人按配置职责分离。
- 服务账号不可交互登录，定期轮换并使用最小权限。

## 3. 数据库权限

- U8账号只读白名单对象，不授予DDL和写权限。
- 外挂应用账号按 API、Worker、迁移、只读报表分离。
- Alembic迁移账号只在发布窗口临时使用。
- 禁止在源码、`.env.example`、日志或任务参数中保存真实密码。

## 4. 审计事件

必须记录：登录和失败、权限变更、方案参数变更、运行创建/取消、质量门禁覆盖、计划调整、冻结/解冻、审核、导出、写回、重试和作废。

审计记录包含：`event_id, actor, action, object_type, object_id, before_hash, after_hash, reason, trace_id, occurred_at`。敏感内容保存哈希或脱敏摘要；审计表只追加，不允许业务账号更新删除。

## 5. API安全

- HTTPS、CORS白名单、CSRF策略与安全响应头。
- 登录、导出、写回和大查询限流。
- 所有过滤和排序字段白名单化，参数绑定防SQL注入。
- 文件导出采用短期签名链接，记录下载人和范围。
- 错误响应不包含SQL、堆栈、连接信息或内部路径。

## 6. 写回控制

写回必须经过冻结、审批、预校验、幂等、数量上限和批次限速。紧急停止开关可以禁用所有写回但不影响只读查询。每个批次支持人工核对，不实现跨库强行回滚。

## 7. 供应链安全

- Python依赖锁定哈希并定期扫描漏洞。
- 镜像使用最小基础镜像，以非root用户运行。
- CI生成SBOM，制品签名后才能部署。
- 密钥通过系统密钥库注入，不打入镜像。
