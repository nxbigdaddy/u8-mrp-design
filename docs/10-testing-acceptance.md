# 10　测试与验收

## 1. 测试分层

| 层级 | 工具/方法 | 重点 |
|---|---|---|
| 单元测试 | pytest | 批量、日历、排序、BOM和状态转换 |
| 性质测试 | Hypothesis | 数量守恒、非负、确定性、舍入边界 |
| 集成测试 | pytest + 测试SQL Server | 事务、批量写入、迁移和重跑 |
| 契约测试 | 固定U8脱敏样本 | 字段映射、状态码、NULL和接口响应 |
| 黄金测试 | 已人工确认的计划数据集 | 逐笔净需求和Pegging结果 |
| 性能测试 | 脱敏生产规模数据 | 时间、内存、并发和数据库压力 |
| 端到端 | Playwright | 创建运行、审核、冻结和发布 |
| 恢复测试 | 故障注入 | Worker退出、网络超时、重复投递 |

## 2. 算法不变量

1. 每个需求满足量＋缺口＝开放需求量。
2. 每个供应的Pegging总量不得超过可用供应量。
3. 不同 `item_dim_key` 默认不可互相冲抵。
4. 同一输入、参数和引擎版本结果确定一致。
5. BOM环路必须阻断，不得无限展开。
6. 计划批量满足最小、最大和倍数约束。
7. 发布重试不能生成重复U8单据。

## 3. 黄金数据集

至少覆盖：单层/多层BOM、共享子件、虚拟件、损耗和固定用量、多个BOM版本、库存完全/部分覆盖、分期供应、超期供需、最小批量和倍数、工作日倒排、冻结订单、取消/提前/推迟例外、自由项/项目隔离。

每个案例保存输入、预期计划、Pegging和业务说明，由主计划员与开发共同签字。

## 4. PoC验收

- 试点范围BOM展开正确率100%。
- 关键物料净需求逐笔准确率不低于98%，差异全部可解释。
- 供需追溯覆盖率100%。
- 相同输入重跑结果一致。
- 对U8生产库的同步负载在约定窗口内，不造成明显阻塞。
- 全量运算时间满足计划批次窗口。

## 5. 写回验收

- 连续三个计划周期只读并行通过。
- 重复请求和超时重试不产生重复单据。
- 业务错误、并发冲突、未知结果均进入正确状态。
- 写回批次可追踪到计划、审核人、请求响应和U8单号。
- 完成写回停止、恢复、备份恢复和故障演练。

## 6. 性能基线方法

使用生产规模脱敏快照，分别记录同步、预处理、每层运算、落库和查询耗时；同时记录峰值RSS、数据库CPU/IO和输出行数。性能优化必须以Profile和SQL执行计划为证据。
